# 旧会员隔离导入准备

客户资料只保留本机；本仓库仅存代码、合成测试和说明。不要把CSV、真实关系JSON、暂存数据库或含客户信息的日志加入Git。

## 已实现

`node scripts/legacy-members.mjs source.csv NEW-isolated.db NEW-report.json`

要求Node 24。源CSV须为UTF-8，包含会员ID和推荐人ID。所有ID按文本保留，不把手机号或昵称猜作登录名。解析带引号、逗号、换行与BOM的CSV；拒绝重复ID、缺失上级、循环及字段数错误。

目标必须是新建的隔离SQLite文件，绝不指定正式数据库。程序只建立legacy_batch和legacy_members，保留全部原始字段、原始上级值及源文件SHA256。零/空上级仅在关系列中以NULL表达，原字段仍保留，不绑定opo。逐行核对原始内容、推荐边，执行外键与完整性检查。重复运行使用新目标，不覆盖已有文件。

暂存记录禁止登录，不创建users、sessions、journal，不生成密码、奖励或资金流水。该脚本是数据保全及映射准备，不是正式用户激活工具。

## 正式导入前仍须解决

|事项|处理要求|
|---|---|
|用户标识|users.id沿用旧ID；用户名必须有经过验证的分配/恢复方案，不能默认把手机号、昵称或旧邀请码当用户名|
|邀请码|取得实际独立邀请码及含义；现有新版username邀请码机制需扩展兼容，不能改写历史关系|
|登录|旧导出不含密码，不生成统一密码；实现用户身份验证后的安全激活流程，迁移不得自动授予管理员权限|
|客户档案|正式库增加来源、联系方式、等级、标签及原始资料关联方案，明确访问权限与保存范围|
|资产|原积分、余额和yochi按原币种单位保全，完整流水与规则对账后另行启用，不直接映射新版ZC/OPOC余额|
|范围|核实全部状态、注销/合并、历史快照人数差异、完整推荐变更历史及最终增量|
|切换|目标备份、回退和源站停写快照通过后，才允许正式导入与切换|

验证：运行`node --test tests/legacy-members.test.mjs`及项目现有测试。实际源资料及执行结果在本机私有迁移目录，不在GitHub。新资料须重新生成SHA256和全量对账，不能沿用旧快照结果。
