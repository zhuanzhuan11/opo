## 现有ZC和DEX的先决核验

现有合约能力是关键路径。必须取得并比对链上运行字节码、已验证源码、ABI、编译器与优化参数，核实代理类型、实现地址、管理员、owner/角色、铸币、暂停、黑名单、收费、豁免、升级历史和总供应量。此前常见代理槽为空的单RPC观察不能证明不可升级或无管理员。

已有可升级机制应保留，但不能为了保留升级任意放开资金权限。若现有ZC不可升级且没有所需收费/销毁能力，外置商城合约不能改变其所有DEX转账行为；需要另行批准迁移或受限路由方案，并清楚说明覆盖边界，不能冒充全网统一扣税。

不要只检查to==pair就认定卖出。添加流动性也会向pair转币；移除、聚合器、闪电交换、池间转账等都要区分。规则要求普通转账与奖励领取不收费，需要通过实际DEX兼容性测试证明。

PancakeSwap官方对fee-on-transfer代币提示不要在V3加流动性。候选方案应先验证V2兼容路径；这不是无需测试即可兼容的保证。V3的NFT流动性仓位也不能套用V2同质LP份额算法。

真burn需实际减少totalSupply并有事件及库存减少对账；转入死地址不一定减少totalSupply。已有ZC不支持burn时必须确定可验收的替代/迁移，不能继续宣传已真实销毁。

本次未取得足以核定升级和收税能力的已验证源码，也未部署合约。合约不能由界面生成按钮自动具备。

参考：https://docs.pancakeswap.finance/trade/trading-faq/swap-faq；https://docs.openzeppelin.com/contracts/5.x/api/proxy。

## 建议拆分的链上开发模块

| 模块 | 用途 | 关键限制 |
| --- | --- | --- |
| ZC适配/卖出费组件 | 在代币/受支持DEX路径落实20%与费用路由 | 先证明可改、明确池和LP操作例外，不任意增发 |
| 认购与销毁组件 | USDT到账、锁定库存、burn、唯一认购事件 | 库存不足/失败补偿、最小额与上限、重入/重放防护 |
| LP质押奖励库 | 有效LP质押、时间累计、三年1亿预算、领取/退出 | 与LP本金隔离，不把奖励库存当用户LP |
| 历史节点释放库 | 核定节点权益、已领取、美元累计额度、ZC折算 | 签名/Merkle证明及nonce，禁止重复计算本金 |
| 城市奖励分发库 | 服务端OPOC快照和日权重产生批次，链上领ZC | OPOC不是链上币；需要可信批次审核、挑战/撤销策略 |
| 费用处理与LP管理 | 10%费用换USDT、配对预留ZC、记录LP凭证 | 滑点/期限/阈值、库存限额、LP归属和锁定 |
| 价格适配器 | 读取可靠价格、检查时效/深度/偏差 | 瞬时现价不可直接作为美元负债发币依据 |
| 治理与安全组件 | 多签、延迟升级、暂停/恢复、角色管理 | 升级不抹掉已领取/归属；紧急权不能任意提用户资金 |

这些是模块建议，不是本次已完成的部署。可复用成熟库，但需锁定版本和提交，独立审计最终组合。OPOC作为不可兑换商城记账积分可先留在受审计的服务端账本，不必为了宣传去中心化而强行上链。

历史节点按动态美元金额释放，不能套一个固定ZC数量的标准线性VestingWallet就宣称满足需求。城市每日跨用户OPOC时间权重也不能在无可信数据来源时凭合约自行得知商城消费。

## 价格预算和资金安全验收

价格方案需选择经审核的预言机，或具有足够流动性和观察窗口的TWAP（时间加权均价）。初始底池只有1万USDT，单池瞬时价容易被影响；价格上升减少发币不等于攻击风险消失。应测试闪电资金、跨池价差和陈旧报价。

历史节点核算：核定投资USDT×1.5，扣除既有确认领取，按计划累计到期美元额度，再以核定价格换算本次ZC。城市核算：总预算500000USDT，按日合格OPOC时间权重分配后再折算。都要固定预算版本、价格来源/时间、精度与唯一领取标识。

资金隔离：会员USDT备用金、订单与商家待结算、认购资金用途、OPOC履约成本、LP配对资金、LP质押本金、历史节点和城市奖励库存分别记录。公开可见地址不代表受审计储备，也不代表多签。

测试异常：报价为0/过期/偏离、ZC不足、USDT不足、链回滚、重复事件、恶意回调、手续费代币少到账、批量Gas不足、暂停时退出、钱包换绑和账号恢复。失败应暂停相关业务并可核对补偿，不隐瞒失败或重复发放。

不要承诺全网无限池都强制20%。目前范围为指定BSC池、任意来源ZC；未登记池、OTC转账和其他交易所需明确技术边界。若未来放开可调整费率，必须有上限、延迟、公告和版本审计，不能静默提高。

## 升级审计和测试链工作

为新业务合约选择可审计的UUPS或透明代理等机制需逐项论证；保留现有升级能力，锁定初始化器、管理员和升级授权，验证存储布局兼容，保存部署清单和实现版本。

关键角色建议由经过项目方确定的多签和时间锁控制；多签人数、阈值与延迟时间属于待批准参数。紧急暂停与升级/提款应分权，不能把紧急功能当任意挪用用户储备的入口。

执行路径：单元/属性/不变量测试 → 指定BSC块高度分叉集成 → 测试链模拟代币端到端 → 独立代码及经济审查 → 管理签名与升级恢复演练 → 明确额度的小额主网验收。测试链资金不是真USDT；不在共享预览中要求用户打测试款到主网地址。

必须验收100ZC卖出分账、买入不收、普通转账不收、添加/移除LP处理、奖励领取不误税、20%手续费代币的路由兼容、退出质押与重复领取、精度尾差及最大预算。

参考：https://docs.openzeppelin.com/contracts/5.x/access-control；https://docs.openzeppelin.com/upgrades-plugins；https://eips.ethereum.org/EIPS/eip-4361。源码/管理员清单和独立报告未取得前，不宣称审计通过。

## 地区范围责任与最后验收清单

目标中国、日本和英语地区不意味着可以在这些地区直接开展同一种代币募集、兑换或收益推广。中国人民银行等部门通知对虚拟货币兑换及相关服务有明确约束；日本金融厅对相关交换/中介等业务有注册要求。必须由适用地区专业人员按实际业务审核，不能只以“无经营主体、人人经营”代替责任方和准入。

对外业务至少明确：签约与售后责任方、服务地区及排除地区、商品/税务/消费者保护、隐私与跨境数据、反洗钱适用性、资金保管责任、积分条款、奖励披露。地区限制不得设计绕过入口。

资料优先级P0：源码ABI/管理员、钱包与库存、LP资料、节点与旧资产全量清单、真实商品/商家/责任方、经营地区审核和云域名控制。P1：核心账本/订单/充值/资格接口、合约组件、取价、独立复核。P2：测试链和小额主网闭环、恢复告警、正式切换。

上线签核应由实际负责人分别确认产品规则、财务对账、技术测试、安全审查、运营履约、地区范围和回滚方案。状态必须有证据链接与具体commit，不以AI回复“完成”代替验收。
