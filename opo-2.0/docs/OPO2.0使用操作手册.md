## 注册登录和邀请关系

1. 从左侧选择中文、日本語或English。切换语言保留当前页面的表单、会员和模拟余额；仅语言偏好长期保存在浏览器。

2. 点击右上角会员登录与注册。邀请码可留空，系统使用平台邀请码opo1；也可填写同一页面已注册会员的专属邀请码。无效代码会被拒绝。

3. 输入非零BSC公开钱包地址和至少8位测试口令。可用虚构地址0x1111111111111111111111111111111111111111。不要使用真实密码、私钥或助记词。

4. 注册后生成唯一会员ID，与钱包余额无关。记录ID和测试口令；退出后可在同一页面内重新登录。钱包地址格式正确不等于已证明钱包所有权，正式版仍需签名认证。

5. 会员中心的我的邀请关系显示自己的邀请码、邀请人、直接邀请人数和会员ID。被邀请人的余额、完整钱包和联系方式不公开；当前没有新增邀请返佣。

6. 想体验邀请：复制本页邀请码，退出当前模拟会员，再用另一虚构钱包和该邀请码注册。不同会员的模拟充值、积分与订单分开。

7. 刷新或关闭会清空模拟账号、关系与订单。现在没有跨设备共享会员或真实账号恢复。不得把这个内存原型用于正式注册收集。

正式会员上线前须实现：服务端唯一ID、密码安全哈希和限流、钱包所有权验证、防重放会话、身份恢复、隐私告知和旧ID映射。旧客户不能统一初始化相同密码。

## USDT充值和资产查询

正式设计：平台充值钱包作为会员USDT备用金，按同一时点与全网会员账本余额、待确认充值和待结算款对账。钱包资产不能因显示在多个会员账号中被重复计为平台收入。

模拟步骤：登录 → USDT充值 → 输入金额 → 创建记录（余额不增加）→ 模拟链上确认 → 当前会员USDT余额增加一次。重复确认不会重复加款。

充值页尚未配置真实收款地址或二维码。不要向旧平台地址、聊天中的陌生地址或示意地址转账。已提供的旧公开收款地址未被自动认定为备用金地址。

我的资产区分商城账本、BSC钱包与币安资金账户。主动连接浏览器钱包可以只读地址、USDT、ZC和BNB；不签名、不授权、不转账，链上余额不自动计入可消费模拟余额。

一键兑换USDT先展示步骤，再打开币安官方P2P。用户需自行完成其适用的身份验证、付款和地区规则。外跳或返回不代表商城到账，不自动成交或给商城记账。

不会钱包的用户：当前可先使用普通支付模拟了解流程。正式银行卡、本地支付、Binance Pay商户和托管钱包并未接入；仅放一个按钮不能替代这些业务系统。

正式充值须校验链56、USDT合约、来源或专属充值地址、金额、确认数和会员映射，以链ID+交易哈希+日志序号防重复，并应对链重组、失败、超时及人工复核。来自交易所的提现通常不是会员个人地址，不能只按交易发送地址自动归属会员。

## 私募OPOC和商品订单

认购规则：单价0.01USDT/ZC，50USDT起，规划库存2亿ZC。支付确认后锁定并最终真实销毁ZC，不向认购人返还ZC；必须以合约实际能力和链上事件验收，不以页面提示代替销毁。

积分规则：认购时按支付金额固定2倍等值OPOC，一年释放。50USDT对应5000ZC销毁和100OPOC总权益，不随ZC市价变化，不是每天获得两倍。1 OPOC以1USDT作消费记账，不代表可兑付USDT。

积分只能购买商城商品；不可提现、转为USDT或直接兑换ZC。当前方案每件商品最多抵扣50%，正式上限、过期、退货后权益处理和商家结算条款仍应书面定版。

测试步骤：先模拟充值 → 我的积分 → 输入50USDT及以上 → 模拟认购 → 推进1/30/365天 → 查看按批次的总权益、已释放与待释放。刷新不会保留记录。

购物步骤：商品分类或广告行业 → 选示意商品 → 测试购买 → 勾选OPOC → 核对现金和积分 → 确认模拟支付 → 右侧订单与退款。支持模拟一次全额退款，恢复现金和已用积分，防重复退款。

商品全部成本包含采购、物流、包装、税费、售后储备、运营、支付和获客摊销，定价为完整成本的2.5至3倍。成本20USDT、倍率2.75时售价55；若抵扣27.5积分，还需27.5USDT。该示例不证明实际利润或结算准备金充足。

现无真实商品目录，示意商品不可宣传为现货。广告行业服务还需交付范围、尺寸材质、修改次数、验收、工期承诺依据和售后责任，不能捏造供应案例。

## LP和城市资格专项奖励

LP质押奖励独立预算1亿ZC，三年按有效质押LP份额及持有时间分配。模拟可质押、推进时间、退出；退出停止未来奖励并保留已累计示例。5.49亿ZC为后续LP配对库存，不能作为个人奖励权重的分母。

城市资格在LP页左侧模拟质押区域下方。仅已释放、未消费的可用OPOC计入：5000至不足10000为城市白名单，可取得商品上传资格；10000及以上为城市服务商。低于门槛暂停相应资格，待释放OPOC不计。服务商具体管理范围仍须确定。

城市专项是三年合计50万USDT等值ZC，不是500万美元，也不是固定发完5000万枚。初始库存5000万ZC从原5.99亿LP库存划出，剩5.49亿。LP质押1亿和历史节点专项1亿不变。

日权重＝合格时间段的Σ（可用OPOC×持有小时）；个人日额度＝当日美元总额度×个人权重÷全体合格权重；本次ZC＝个人美元额度÷核定ZC价格。服务商只计一次，不再叠加白名单权重，也不消耗OPOC。

演示按1095天，日总额度约456.621005USDT。个人权重占三分之一时，日额度约152.207002USDT：价格0.01时约15220.700152ZC；价格0.02时约7610.350076ZC。美元额度不变，币数随价变化。

展开资格与奖励模拟计算可改余额、合格小时、其他权重和价格。输入不增加真实权限或余额。价格下跌时初始库存可能不足；补足来源、取价、实际日期、精度、日切与无人合格日处理须在上线前定版。

## 历史节点及分红与卖出费用

左侧节点及分红只对应经核定的前期公链投资人，不接受新投资。每1000USDT为1份算力，三年本息总权益合计为原投入的1.5倍USDT等值ZC，不再额外返还本金。

| 历史投入USDT | 算力份数 | 三年本息等值USDT |
| --- | --- | --- |
| 1000 | 1 | 1500 |
| 4000 | 4 | 6000 |
| 10000 | 10 | 15000 |

每次释放按当时核定ZC价格折算；三年ZC总数量不预先固定。原始记录、币种、金额、投资时间、过往已领取、受益人和会员ID必须对账，不能以用户自行填写的金额直接授予算力。非1000整倍数的零散投资暂不舍入。

历史专项暂留1亿ZC，统计后精确核定，剩余可作为经平台授权使用的机动ZC。已分配的节点储备与机动额度分开；动态折算下仍需持续核对储备。

任何来源ZC向指定BSC底池卖出均收20%：10%平台收益，10%换USDT并配对平台预留ZC增加LP。买入、普通转账、奖励领取不收这项卖出费。DEX费、滑点和Gas另计。上表是卖出费用前权益。

示意：若最终合约按ZC输入扣费，卖100ZC时80ZC用于交换、10ZC平台、10ZC进入费用处理；后者换USDT后配对预留ZC。实际成交USDT由池价、深度、滑点决定，并非页面按固定汇率承诺。收费币种和执行路径须在合约规格中确认。

现有ZC源码和升级权限尚未完成核验。不能只靠商城按钮强制外部DEX收税，也不能把向池地址转账一律当卖出而误收添加LP的手续费。

## 商家后台和团队操作分工

商家使用：准备真实商品、授权图片、完整成本、SKU库存、供货与售后资料。取得资格后仍需服务端授权和商品审核。当前上传按钮仅标记待接入，不会实际发布商品。

管理员使用：独立后台原型仅展示全部成本输入、2.5至3倍率和抵扣后现金测算。它不是已保护的管理系统，没有真实身份验证，不应填写商业机密。正式系统需管理员MFA、审核发布、操作审计与分离权限。

财务使用：核定充值、准备金、认购销毁、节点记录、每日权重、奖励预算和退款。用户商城USDT备用金、商家待结算、OPOC履约成本、LP配对资金、节点及城市奖励库存分别对账，不得混用。

技术使用：Node24.18.1环境进入opo-2.0，运行npm run preview:model，打开127.0.0.1:3211。npm run test:model验证当前模型。旧npm start为既有服务端沙盒，不能直接视为新界面的正式资金后台。详见交付运行入口文档。

宣发使用：可分享公开模拟链接，展示首页、会员、钱包、积分、LP、节点、FAQ和说明。不使用模拟销量、收益、商品库存、已审计、已持牌等未经核实的承诺；正式募集与服务地区需专门审核。

维护使用：分支提交、PR、CI、人工审核后合入；不能由同一作者自批。依赖与Actions固定版本/提交，密钥不进仓库。AI可协助修复与测试，真实资金、合约升级和生产发布需有权人员审核，当前没有已启用的24小时无人值守维护。

## 常见故障和正式启用前检查

账号消失：先确认是否刷新了页面。当前内存演示清空后不能恢复；正式系统必须部署持久数据库、备份和恢复流程。

充值未到账：模拟先点确认；正式须查链、合约、金额、哈希和确认数，进入受控人工核对，不重复补账，不接受聊天截图作为唯一付款凭证。

钱包余额不对：确认BSC链、正确钱包、代币精度和查询区块；换账户清除旧数据。不要用余额生成会员ID，也不要把币安余额当链上钱包余额。

积分不足或资格暂停：分别查看可用、待释放和已消费OPOC。降级按当前可用余额，服务商降到5000以上仍可保留白名单，不能重复领取两份城市权重。

价格或奖励异常：正式系统在报价过期、价差过大、深度不足或库存不足时应暂停相关发放并告警，不静默用0价或操纵性瞬时价格结算。恢复须保留审计证据。
