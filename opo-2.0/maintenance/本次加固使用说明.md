# 本次加固使用说明

本版仍为sandbox，禁止充值；正式条件见 docs/上线核查与剩余条件.md。

## 检查与预览

使用项目要求的Node.js 24版本，在opo-2.0执行：

```sh
npm run check
node backend/server.mjs
```

浏览器打开 http://127.0.0.1:3200 。`npm run readiness`目前应返回退出码1，代表有真实上线阻塞，不能当作测试失败修掉。

## 可调整提成

后台“参数与审计”支持六项分账和两项释放加速。100表示1%，不是100%。调整必须写原因，提交后由另一管理员批准；批准前不生效，提交人不能自行复核。所有新规则只影响新订单，已有订单保持原快照。没有第二管理员时提案保持待审，不允许AI伪装第二名负责人。

初始化第一个管理员沿用README的bootstrap方式。第二管理员需由授权系统操作者在后续账号权限管理完成后设置；本版没有公开的“自升管理员”接口，不要直接修改角色字段来冒充生产权限流程。

## 动态验证码

执行 `npm run secrets:init` 仅创建本机 .secrets/mfa-key，不显示值。此命令拒绝覆盖旧密钥；旧数据库已绑定验证器时不能换一个密钥继续使用。将密钥单独加密异地备份，并限制文件读取权限。Windows环境还须按部署账户设置ACL，POSIX mode不能替代Windows ACL。

本机启动前设置OPO_MFA_KEY_FILE为该文件绝对路径；Docker Compose自动挂载此文件。登录后台“账号安全”，输入当前密码，在验证器手动加入页面给出的密钥，再输入六位验证码确认。绑定后其他会话失效，后续登录须填动态验证码；同一码不能重复使用。未实现自助MFA恢复，验证器及服务器密钥丢失必须由授权运维按后续恢复流程处理，不能删除表绕过。

## 备份与恢复验证

```sh
npm run backup
node scripts/restore-check.mjs /absolute/path/to/backup.db
npm run reconcile
```

备份生成数据库和SHA256说明，检查完整性及外键；恢复检查只在临时副本进行并清理副本，不覆盖业务库。对账只检查内部账本，不证明链上资金存在。备份和验证器密钥属于敏感资料，不上传源码仓库。自动异地备份、真实恢复和链上重放仍需部署后实施。

## 链上只读核对及升级保留

设置OPO_RPC_URL为HTTPS节点、OPO_ZC_ADDRESS为待核验公开地址，运行 `npm run chain:inspect`。脚本只调用读取接口，不接收私钥，不转账、不升级。

仓库未提供原合约，所以本次没有改写或放弃任何链上权限。若原合约可升级，后续保留原代理地址及授权路径，先取得原实现源码、编译参数、存储布局和历史升级记录；通过布局兼容验证及测试网演练后，准备由授权多签执行的升级交易。不要把空的常见代理槽认定成“永远不可升级”。新建外围合约的升级方式须另行实现和验证，不声称本版已有。

## 持续检查与部署

仓库根目录 .github/workflows/opo-checks.yml 运行语法与回归检查，使用固定上游提交的GitHub Actions；它不自动发布或合并。需要在仓库配置分支保护后，才能要求检查通过才允许合并。CI是否运行及结果以GitHub实际记录为准。

Docker配置仍只绑定127.0.0.1并运行sandbox，本次环境没有Docker，配置未执行验证。正式主机需要HTTPS反向代理、明确来源、仅信任指定代理的客户端地址处理、外部监控及告警。当前限流默认按直接连接IP计数，代理后的访客可能共享限额，必须在正式环境完成代理配置和验证。
