# 部署说明

## 本机 Windows / macOS

安装Node.js 24.18.1后，在根目录运行 `node backend/server.mjs`，打开 http://127.0.0.1:3200 。运行不依赖外部CDN，不需要npm install。管理员初始化见根README。

## Docker测试部署

从根目录执行 `docker compose -f deployment/compose.yaml up --build -d`。默认仅监听本机127.0.0.1，数据保存在opo-data卷。该Docker配置本次未在本机运行验证（没有Docker运行环境），不要把文件存在当作部署成功。

## 正式服务器准入

当前生产启动被明确阻止。解除限制前必须完成：docs/实施状态与上线缺口.md中的资金规则、真实支付适配、合约审计、MFA、权限分离、完整售后、压测、备份恢复演练、服务条款和运营授权。

云主机部署需要项目方选择服务账户、预算及域名。公网运行应在反向代理后使用HTTPS，配置固定OPO_ORIGIN，保留Cookie安全属性。不要直接公开测试注册和测试额度入口；不要将服务器监听0.0.0.0后就称正式上线。

数据库目录、备份及密钥不放静态站点目录，不提交GitHub。源代码公开仓库可以同步资料，但不能承载Node业务服务器和SQLite数据库。

## 环境变量

OPO_MODE默认sandbox；OPO_DATABASE为私有数据库绝对路径；PORT默认3200；HOST默认127.0.0.1；OPO_ORIGIN为客户端唯一来源。OPO_ADMIN_USER/OPO_ADMIN_PASSWORD只在初始化时使用。deployment/.env.example是无密钥模板，不会被程序自动加载。

## 回滚

更新前备份数据库并记录Git提交。停止旧进程后启动新版本。失败时恢复前一版本与匹配备份；禁止新旧版本同时写同一个数据库。外部资金接入后，回滚必须先对账链上真实状态，不能通过旧数据库覆盖已经完成的交易。
